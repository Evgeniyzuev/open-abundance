# ИИ-разбор заметок и список Abundance (план, NOTES-AI-001)

Статус: план, код не писали. 24.10.2026, по запросу Evgen.

## 1. Что есть сейчас (проверено по коду)

- Заметки живут только на устройстве (IndexedDB). `/api/notes/sync` ничего не сохраняет на сервере, это заглушка. Значит, для любого разбора на сервере текст заметки надо отправить явно, с согласия человека.
- Чат с Новой тоже локальный. Писать человеку с сервера можно только через «Входящие от Новы»: таблица `nova_inbox_messages`, Claude пишет через `/api/internal/nova/inbox`, приложение забирает при открытии чата.
- ИИ-аналитика и проверка эссе запускаются из Claude Code вручную скриптами (`pnpm analytics:daily`, `pnpm essay:review --list / --submit`). Результат пишется в базу, приложение показывает его, когда человек в приложении. Так что «сервер» у нас есть (Vercel и Supabase), нет только ИИ, который работает сам постоянно.
- Быстрый ИИ (Gemini, Groq, Cerebras через `lib/ai/providerGateway.ts`) уже работает на сервере и отвечает за секунды.
- Кнопка «AI» у заметки сейчас только интерфейс.

## 2. Главная идея

Одна очередь запросов на разбор, два исполнителя, и человек никогда не ждёт с открытым окном.

1. Человек нажимает «AI» и выбирает, что сделать с заметкой (раздел 3).
2. Кнопка сразу становится ⏳, внизу надпись «Будет разобрано ИИ-ассистентом». Окно можно закрыть.
3. Запрос с копией текста уходит в таблицу на сервере.
4. Срочный разбор делает быстрый ИИ сразу на сервере (Нова), обычно за 5–20 секунд. Глубокий разбор забирает Claude Code: вручную скриптом или по расписанию.
5. Результат пишется в ту же запись. Приложение при открытии забирает готовые ответы, кладёт в заметку, ⏳ меняется на ✨, в «Входящих» появляется отметка «готов разбор».
6. После доставки текст заметки на сервере стирается (как у входящих Новы), остаётся только служебная строка без текста.

Исключение: «Обсудить» и «Поддержать» лучше сразу. Они открывают чат с Новой, где заметка уже вставлена, и идут как обычный разговор, без очереди.

## 3. Как разобрать: выбор из готовых вариантов, а не допрос

Вместо цепочки вопросов человек одним нажатием выбирает, что он хочет. Вариантов немного, сверху те, что подходят к типу заметки.

Сразу (живой ответ, чат с Новой):
- Поддержи меня. Нова отвечает тепло и коротко, может разделить эмоцию (посмеяться вместе, погрустить), без советов, если о них не просили.
- Обсудим. Открывается чат с заметкой внутри.

Можно потом (через очередь, срочно или глубоко):
- Разложи по полкам. Что это: задача, желание, идея, наблюдение, чувство. Предлагает список, куда перенести, и одну кнопку «Перенести».
- Совет или мнение. Один короткий совет или честное мнение, с пометкой, что решать человеку.
- План. Цель по SMART и 3–5 шагов. Шаги можно одним нажатием превратить в задачи.
- Конкретные задачи. Сразу список задач с датами, человек отмечает галочками, какие создать.
- Связи. Найти похожие заметки, повторы и пересечения среди других заметок (раздел 5).

Тип заметки (мысль, чувство, наблюдение, задача) определяется простыми правилами на устройстве, без ИИ. От типа зависит только порядок кнопок: для чувства сверху «Поддержи», для задачи сверху «Конкретные задачи».

Вопрос человеку допустим один и только когда без него ответ будет пустым. Он показывается как часть результата («Если хочешь, уточни: ...»), а не перед ним.

## 4. Срочный и глубокий

| | Срочный | Глубокий |
|---|---|---|
| Кто делает | Нова на текущем шлюзе (Gemini, Groq, Cerebras) | Claude Code (как ИИ-аналитика) |
| Когда | сразу на сервере | при ближайшем запуске: вручную или по расписанию |
| Что видит | одну заметку | заметку и, с согласия, связанные заметки и общий контекст |
| Цена | бесплатно в пределах лимитов | время Claude Code |
| Лимит | общий лимит ИИ-инструментов (30 в день) | например 3 в день на человека |

Варианты запуска глубокого разбора, по порядку рекомендации:

1. Расписание Claude Code: облачная задача раз в 3 часа (или 2 раза в день) запускает `pnpm notes:review`, разбирает очередь и пишет ответы. Никто не ждёт вручную, сервер не нужен.
2. Вручную, как сейчас эссе: Evgen или оператор запускает скрипт, когда удобно. Подходит на старте, пока запросов мало.
3. Позже, если запросов станет много: глубокий разбор моделью побольше прямо в cron Vercel. Дешевле по времени, но слабее Claude.

Человеку честно пишем срок: «Срочный: через минуту. Глубокий: обычно в течение дня».

## 5. Связи между заметками

- На устройстве ведём локальный индекс сырых заметок: нормализованный текст и простые признаки (слова, даты, списки). Повторы и очень похожие заметки находятся прямо на телефоне без ИИ и показываются в результате: «Похоже на заметку от 12 окт.».
- Для смысловых связей (одна тема разными словами) глубокий разбор получает, с отдельной галочкой согласия, короткие выдержки из 10–20 последних заметок того же списка. Без галочки разбирается только одна заметка.

## 6. Список Abundance

- Второй встроенный список рядом с «Входящими». Его нельзя удалить, но оба встроенных можно скрыть. В режиме «Изменить списки» вместо крестика у встроенных показывается глазик, скрытые возвращаются там же.
- Рядом с названием кнопка (?), текст: «Мысли про пост-дефицит, ИИ и изобилие. Идеи, предложения и замечания про приложение и всё остальное. Заметки из этого списка видит команда Open Abundance и ИИ, они могут использоваться для развития ИИ и проекта».
- Заметки из этого списка отправляются на сервер (только они), потому что их смысл в том, чтобы их прочитали. Первый раз приложение спрашивает согласие этим же текстом.

### Выгрузка в документы

Раз в день (вместе с ИИ-аналитикой) скрипт `pnpm abundance:export` забирает новые заметки из списка Abundance и дописывает их как есть, только текст, с датой:

- `docs/abundance/FROM_OPERATOR.md` — заметки оператора (Evgen);
- `docs/abundance/FROM_USERS.md` — заметки всех остальных, без имён, только псевдоним и уровень.

Дальше эти два файла разбираются отдельно, как входящие: сверка с тем, что уже есть, подробности, планы доработок.

Важно: репозиторий публичный. Всё, что попадает в main, видят все. Поэтому для пользовательских заметок есть два варианта: (а) держать `FROM_USERS.md` вне публичного репозитория (в закрытом хранилище или в базе, а в репозиторий класть только наши выводы), или (б) класть в main, но тогда в тексте согласия прямо писать «может быть опубликовано», и перед выгрузкой убирать телефоны, почты и ссылки. Рекомендую (а) для пользователей и обычный `FROM_OPERATOR.md` в main.

## 7. Что нужно построить (порядок)

1. Меню кнопки «AI» и состояние ⏳ / ✨ на заметке, надпись «Будет разобрано ИИ-ассистентом». Только интерфейс и локальное состояние.
2. «Поддержи» и «Обсудим» через чат Новы с заметкой внутри (сервер не нужен, уже есть).
3. Таблица очереди `note_ai_requests` (миграция): человек, режим (срочный или глубокий), вариант разбора, копия текста, статус, результат, время. Чистка текста после доставки, удаление строк через 14 дней.
4. API: поставить в очередь, забрать готовые, подтвердить доставку. Срочные разбираются сразу в том же запросе к шлюзу, ответ сохраняется даже если человек закрыл приложение.
5. Скрипт для Claude Code `pnpm notes:review --list / --submit` по образцу проверки эссе, затем расписание.
6. Карточка результата в заметке с кнопками действий: создать задачи, перенести в список, добавить желание.
7. Встроенный список Abundance, скрытие встроенных списков, (?) и согласие.
8. Таблица для заметок Abundance и `pnpm abundance:export` в документы.
9. Локальный поиск повторов и похожих заметок.

Шаги 1–2 можно сделать без миграций. Для 3–8 понадобятся две миграции, Evgen применяет их сам.

## 9. Решение Evgen (24.10.2026) и как сделано

- Сырые заметки Abundance в репозиторий не выгружаются (репозиторий публичный). Они лежат в таблице `abundance_notes` в Supabase. Claude в ежедневной процедуре читает новые (`status = new`), отмечает каждую (`read / valued / done`), чтобы не читать второй раз, и пишет готовые предложения и замечания в [docs/abundance/PROPOSALS.md](abundance/PROPOSALS.md), без имён и цитат, по которым можно узнать человека.

Остальные варианты уходят в очередь `note_ai_requests`: быстрый разбор отвечает шлюз ИИ за минуту, глубокий (до 3 в день) делает Claude в ежедневной процедуре. Кнопка становится ⏳, ответ приходит в заметку (✨), текст заметки на сервере стирается после доставки.
