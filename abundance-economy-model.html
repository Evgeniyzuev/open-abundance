Модель экономики Abundance

Сценарный прогноз Treasury, Wallet, Core, вознаграждений и внутреннего рынка. Предустановленные значения демонстрационные; все параметры изменяемы, расчёт выполняется локально.

Важно: это сценарная модель, а не гарантия дохода, внешней ликвидности или возможности вывода. Core — внутренняя невыводимая величина; прогноз Wallet-выплат служит для планирования резерва.
Период и резерв

Текущее покрытие = Treasury / Wallet. Покрытие с будущими выплатами дополнительно включает прогноз Wallet-выплат от существующего Core. «Доп. Core в резерве» показывает только запас планового Wallet-резерва, а не разрешённую награду.

Ликвидность и расходы

Один знаковый поток задаёт среднюю динамику: плюс пополняет Treasury и Wallet 1:1, минус создаёт запрос на вывод. Инвестируемая часть Treasury ежедневно получает заданную сценарную доходность. Внутренние услуги сжигают Wallet и начисляют заданную долю Core; Wallet наследуется целиком без изменения совокупного Wallet. Неактивность переводит Core в отдельную категорию.

Core и вознаграждения

Core нельзя передать, уменьшить, наследовать или конвертировать обратно в Wallet. Доход от Core начисляется ежедневно без исключений. При неактивности Core только переводится в отдельную категорию — совокупный Total Core не меняется — и получает 100% reinvest; Wallet передаётся наследнику. Реферальная награда и комиссии Wallet → Core — экспериментальные, по умолчанию нулевые.

Marketplace

Marketplace — отдельный оборотный контур. Покупки и продажи перераспределяют Wallet между участниками; на совокупное обеспечение влияют только сожжённые комиссии.

Анализ модели и экономики Open Abundance

Это аналитическая вкладка: базовые принципы, механики, закономерности роста и открытые вопросы. Она не влияет на расчёт модели.

1. Базовые принципы: неубывающий Core и ежедневный доход

Каждый день Core генерирует доход gross = core × dailyRatePct/100 (0.0633%/день ≈ 26% годовых эффективно). Скорость Core не убывает никогда: часть идёт в reinvest (сложный процент), остальное — в Wallet как выплата. Неактивный Core получает принудительно 100% reinvest и не создаёт Wallet-выплат. Total Core никогда не уменьшается — при неактивности он лишь переводится в отдельную категорию Inactive Core.

Это система «обязательств с плановым резервом»: Core — внутренняя величина-притязание, платёжеспособность обеспечивается покрытием Treasury / Wallet ≥ Норма резервирования. Модель учитывает будущие выплаты существующего Core (forwardWalletPayout) в «покрытии с будущими выплатами» и в safeCoreBudget.

2. Механики: резерв → челленджи → рост Treasury + Core

  • Свободный резерв: F = Treasury − Wallet × Норма.
  • Награды за челленджи/мес: challengeRewardPct × F — начисляются Core участникам.
  • Рост Treasury от челленджей: challengeRewardPct × F × challengeTreasuryRevPct — часть выпущенного Core тут же получает реальное обеспечение.
  • Сжигание Wallet (постоянное, marketplace-комиссии, Wallet → Core) снижает обязательства и улучшает покрытие.
  • Неактивность переводит Core в Inactive с 100% reinvest — автоматический деливеридж: Core перестаёт генерировать Wallet-обязательства.

Круг устойчивости: F растёт, когда Treasury растёт быстрее Wallet: конверсия челленджей в Treasury, инвестиционная доходность, финансирование без обязательств. Wallet сдерживается сжиганием и высоким reinvest.

3. Закономерности для роста

  • Оптимум наград за челленджи: модель даёт ограничитель safeCoreBudget = (T / norm − W − forward) / recipientFactor. Поскольку челленджи приносят Treasury k×F, выдача c×F при k>0 не только не вредит, но увеличивает F на следующий месяц — ограниченная положительная петля F' = F(1 + c·k) − расходW. Практический оптимум — максимизировать c при k, держа rewardBudgetExcess около нуля.
  • Совокупный reinvest: фактор будущей выплаты factor = d·(1−r)·((1+d·r)^n − 1)/(d·r). При r=0 растёт линейно, при r→1 → 0. Высокий reinvest — главный инструмент, чтобы Core рос, а обязательства не взрывались.
  • Сжигание Wallet математически эквивалентно повышению нормы покрытия: снижает W без изменения T.
  • Рост Treasury распадается на 3 источника (уже разделены в модели): от челленджей, от пополнений Wallet/финансирования, от инвестиций.

4. Вопросы и что не учтено

  • Операционные расходы системы из Treasury. Сейчас всё сжигание — Wallet. Реальные операционные расходы (команда, инфраструктура, юристы) обычно идут из Treasury. Без этого модель переоценивает здоровье. Вопрос: какая доля операционных расходов идёт из Treasury, и как она снижается по мере роста?
  • Доля расходов пользователей, выводимая из Wallet → Treasury. Если пользователи покупают за Wallet реальные активы (недвижимость и т.п.), это вывод из Treasury 1:1. Идея: эта доля должна снижаться по мере того, как система делает внешнеторговый баланс профицитным — мы не только покупаем снаружи, но и продаём, пополняя Treasury.
  • Прирост пользователей не привязан к челленджам. Сейчас growthPct задаётся вручную. Правильнее: newUsers = подтверждённые челленджи × конверсия привлечения % + органический рост.
  • Двойственность резерва: база челленджей F = T − W×norm не вычитает forward, а safeCoreBudget вычитает. Стоило бы сделать базу F = T − (W + forward)×norm.
  • Экспоненциальный компоундинг на 360 месяцев может упираться в MAX_VALUE — нужен сигнал о «взрывном росте».

5. Резюме контура для добавления

Челленджи → (i) Core-награды, (ii) конверсия в Treasury, (iii) привлечение новых пользователей по конверсии → рост Wallet-потока и сжигания → рост свободного резерва → больше челленджей.

Два обязательных ограничителя устойчивости: реальные активы, покупаемые из Treasury, и операционные расходы из Treasury. Без них модель оптимистична.

Marketplace — отдельный оборотный контур

Marketplace не связан с ростом Core, Wallet, Treasury и обеспечения — это чисто внутренняя экономика. Покупки и продажи перераспределяют Wallet между участниками; на совокупное обеспечение влияют только сожжённые комиссии (они уже включены в сжигание Wallet в основной модели).

Ключевые параметры

  • Средний чек (averageOrder) — размер сделки.
  • Market match (marketMatchPct) — доля спроса, совпавшая с предложением.
  • Завершение сделок (marketCompletionPct) — доля завершённых escrow-сделок.
  • Возврат незавершённых escrow (marketRefundPct) — доля возврата.
  • Комиссия Marketplace (marketplaceFeePct) и сгорающая доля (marketplaceFeeBurnPct) — комиссии сжигают Wallet.
  • Скорость Wallet (walletVelocityCap) — максимальная скорость оборота Wallet за месяц.

Показатели

  • GMV — стоимость завершённых сделок (не доход и не внешняя ликвидность).
  • Спрос и предложение по когортам (покупатели × покупок × чек; продавцы × продаж × чек).
  • Возвраты, комиссии, сожжённые комиссии.
  • Изменение общего Wallet = −сожжённые комиссии (fee-free торговля не меняет Wallet).
