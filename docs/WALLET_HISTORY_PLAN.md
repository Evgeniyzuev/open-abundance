# История Wallet и Core: баланс после операции и полный чек (HIST-001)

Статус: баланс и пропавшие типы сделаны (2026-10-17), полный чек в плане.

## Сделано

- **Покупки в Лавке не показывались.** История Wallet брала операции из белого списка типов, и `system_shop_purchase` в нём не было. Список убран: теперь видны все операции кошелька. Известные типы получили названия («Покупка в Лавке», «Реферальная награда», «Предмет Сада Core», «Afterburn: перенос в Core»), неизвестные показываются как «Операция», а не под чужим названием.
- **Баланс после операции вместо «Источник».** Во второй строке каждой операции Wallet и Core теперь «Баланс: …».
  - Wallet: точное значение берётся из `wallet_ledger.balance_after`. Ночные выплаты процентов в Wallet в журнал не пишутся, их баланс считается от соседних записей.
  - Core: у ежедневных начислений есть точное `core_after`, остальные строки восстанавливаются между ними от текущего баланса.
  - Правило честности (`lib/historyBalance.ts`): если цепочка расходится с точным значением (в списке нет какой-то операции), строки между ними показывают пустое место, а не неверное число. Без единого точного значения в окне баланс не показывается.
- В историю Core добавлены реферальные награды, выплаченные в Core, чтобы цепочка была полнее.
- Проверка на реальных данных боевой базы (без вывода личных данных): у единственного пользователя с покупками в Лавке 32 строки истории, баланс виден во всех, обе покупки на месте.

Тесты: `pnpm test:history-balance`.

## Дальше: полный чек при раскрытии строки

Идея: строка операции раскрывается и подгружает подробности только по нажатию.

- Эндпоинт `GET /api/wallet/history/[id]` для одной записи журнала и `GET /api/core/history/[id]` для строки Core. Это один запрос по индексу на одно раскрытие, нагрузка небольшая, при открытии списка ничего лишнего не грузится.
- Что показывать по типам: покупка в Лавке (предмет, редкость, цена), предмет Сада (предмет, перенос в Core), перевод (контрагент по нику, комментарий), Маркет (объявление, сделка, статус, комиссия), крипто-пополнение и вывод (сеть, актив, курс, хэш), реферальная награда (за кого и за что, без личных данных приглашённого), Afterburn (дата ночного запуска, сумма), начисление (ставка, процент реинвеста, сколько в Core и сколько в Wallet).
- Приватность: показываем только свои данные и ник контрагента, не идентификаторы.
- Лимит: один открытый чек за раз, кэш на время сеанса.

Оценка: небольшая работа на каждый тип, самая объёмная часть Маркет и крипто-операции. Начинать с Лавки, Сада, Afterburn и начислений: данные уже есть в метаданных журнала.

## Известные ограничения

- Баланс Core между точными значениями восстанавливается расчётом. Если операция, меняющая Core, не попадает в историю (например, ручная корректировка), строки рядом покажут пустое место.
- Чтобы баланс Core был точным везде, нужно записывать `balance_after` при каждом изменении Core (отдельный журнал Core). Это изменение платёжного кода и миграция, поэтому только по решению.
