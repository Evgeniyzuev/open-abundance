# Ключевой цикл желаний Open Abundance

Статус: первый срез реализован и передан на User QA 2026-09-09. Текущий приоритет и фактические проверки находятся в [MASTER_KANBAN.md](MASTER_KANBAN.md).

## Цель

Сделать главным опытом приложения короткий цикл:

```text
увидел возможность → захотел себе → выбрал ближайшее желание
→ сделал маленький шаг → увидел реальный результат → вернулся продолжить
```

Эмоциональный переход: сравнение с чужим результатом быстро превращается в надежду и личное действие. Демо-истории всегда сохраняют маркировку; финансовый прогресс не подменяет полезный результат человека.

Новый демонстрационный маршрут и новый домен данных не создаются. Используются существующие `feed_posts`, `recommended_wishes`, `wishes`, челленджи, Core и Wallet. `components/RecommendedWishes.tsx` остаётся legacy; рабочий экран — `components/WishesApp.tsx`.

## Этап 1. Один законченный маршрут

Шесть существующих демо-историй связываются по стабильному `source_key` с шестью существующими рекомендациями. В подробностях истории доступно действие «Хочу так же». Сервер создаёт приватную личную копию рекомендации через существующий `/api/wishes`; `source_recommended_wish_id` исключает дубль.

После добавления открывается личное желание. Участник сам делает его ближайшим. Для первого среза выбор хранится локально отдельно для каждого аккаунта; это явно ограничение прототипа, а не независимое серверное право.

Home показывает образ желания, Wallet отдельно от Core, доступный ежедневный доход, расчётный срок без будущих наград и первый шаг на одну минуту: сформулировать первый заметный результат. Затем можно открыть существующие задания, попросить подсказку, выбрать другое или пропустить день без потери достигнутого.

## Этап 2. Проверка понятности

Проверка 2026-09-09 обнаружила два препятствия: после «Хочу так же» загрузка завершалась без созданного желания, а переход к пути и смысл первого ориентира были непонятны. В исправлении добавлены повтор запроса после обновления истёкшей сессии, видимая ошибка над лентой и прямые подсказки перед выбором ближайшего желания и сохранением ориентира. Повторная пользовательская проверка ещё не выполнена.

Основатель проходит мобильный сценарий без предварительного объяснения и подтверждает:

1. понятно, что история демонстрационная;
2. действие «Хочу так же» находится самостоятельно;
3. повторное добавление не создаёт второе желание;
4. ближайшее желание выбирается явно;
5. различаются Wallet, Core и ежедневный доход;
6. первый заметный результат можно сформулировать и найти после перезагрузки;
7. отказ и пропуск не выглядят наказанием.

Только после этой проверки расширяются данные и навигация.

## Этап 3. Постоянный путь и типы целей

После подтверждения UX в `wishes` добавляются серверные поля ближайшего желания и типа цели: разовая покупка, регулярная потребность или нефинансовая цель. Выбор ближайшего выполняется атомарно и синхронизируется между устройствами.

- Разовая цель: показываются доступные средства, остаток и срок по текущему доступному доходу.
- Регулярная цель: показывается доля месячной потребности, покрытая доходом за 30 дней; без известного источника роста срок не обещается.
- Нефинансовая цель: показываются ближайшая веха и действие без искусственной цены.

Тестовые значения `1 000 Core`, `$90`, `$100` и `$30 в месяц` используются только в детерминированных проверках формул.

## Этап 4. Полезная работа и подтверждённый результат

Навигатор выбирает одно подходящее задание примерно на 15 минут и показывает результат, критерий приёмки и награду. Состояния: `доступно → начато → отправлено → на проверке → принято`.

Предварительный экран может показать эффект `+25 Core`, но фактический Core меняется только через существующий журнал после подтверждённой приёмки. После принятия экран подчёркивает созданную человеком ценность, затем награду и пересчитанный путь.

## Этап 5. Возвращение и простая навигация

Без ближайшего желания первое открытие ведёт к историям; с ближайшим — к его пути. Явная deep link сохраняет приоритет. После User QA основными направлениями становятся «Лента», «Желания» и «Мой путь»; остальные возможности остаются доступны из дополнительного меню.

## Этап 6. Скорость сторис и удержание

Сначала измеряются время API и изображений. Галерея получает облегчённые данные, подробности догружаются после открытия, а медленные внешние обложки заменяются быстрыми миниатюрами с проверенным происхождением.

События цикла: показ и нажатие «Хочу так же», добавление, выбор ближайшего, открытие пути, сохранение первой вехи, начало/отправка/принятие задания и добровольное возвращение. Удержание подтверждается повторным использованием, а не количеством добавленных желаний.

## Техническая проверка

Обязательны typecheck, lint, build, `git diff --check` и одна ограниченная браузерная попытка по [DEVELOPMENT_RULES.md](DEVELOPMENT_RULES.md). Проверяются duplicate protection, изоляция локального выбора по аккаунтам, перезагрузка, очистка удалённого/архивного желания, reinvest 100%, нулевой доход и отсутствие выдуманного финансового начисления.
