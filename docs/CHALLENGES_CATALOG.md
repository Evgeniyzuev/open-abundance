# Каталог челленджей Abundance Effect

Документ описывает текущий набор челленджей и предлагает новые для увеличения привлечения пользователей, роста Core (инвестиций), пополнения Wallet (ликвидности), расширения внутреннего рынка и торговли между пользователями.

## 0. Сверка с концептом и мастер-планом

Концепт `Abundance System` шире текущего каталога: он описывает AI-координированную систему роста, доверия, навыков, помощи другим, команд и создания ценности. Мастер-план `OPEN_ABUNDANCE_MASTER_PLAN.md` приземляет это в MVP через PWA, Today, Wishes, Core/Wallet, стартовые челленджи, соцленту и AI Coordinator.

Главное расхождение каталога: предлагаемые челленджи слишком быстро уходят в деньги, переводы и marketplace, хотя концепт требует сначала провести пользователя через самопонимание, первый реальный шаг, видимый прогресс, вклад в других и доверие. Для MVP стоит усилить первые 1-3 уровня неденежными, хорошо проверяемыми действиями, а marketplace-челленджи оставить как дорожную карту после Wallet-to-Wallet, публичных профилей, базовой модерации и ledger-источника роста.

Что доработать в каталоге:
- добавить челленджи на self-discovery, skill inventory, превращение желания в 3 задачи, первый публичный progress story, помощь другому пользователю и подтверждение доверия;
- разделить `Core growth` и реальные пополнения: ранние челленджи должны поощрять действие и маршрут, а не подталкивать к onramp до готовности платежной инфраструктуры;
- не начислять Wallet как системную награду; Trust/репутацию отложить до отдельной Trust-системы;
- для переводов, команд и поддержки целей сразу задать анти-накрутку: non-self операции, минимальная сумма, rate limit, уникальные контрагенты, статус `completed`, связь с `wish_id` или конкретной сущностью;
- у каждого нового челленджа должен быть конкретный `verification_logic`, а не только `auto` / `manual` в описании.

Статус 2026-06-11: реализованы автопроверки `ai_message_sent`, `profile_strengths_filled`, `wish_steps_created`, `first_growth_post_published`, `reinvest_enabled`, `has_referral`, `team_contact_active`, `skill_profile_completed`. Добавлены челленджи без Wallet-наград и без репутации: Personal Value Map, Turn Wish Into 3 Steps, First Growth Story, Enable Reinvestment, Skill Passport, Team Welcome.

Статус 2026-06-11, оффер и понимание: вкладка Goals -> Results заменяет прежний `growth`-слот и показывает общий оффер `Abundance System`: маршрут к $1,000,000 Core за 20 уровней. После первого прочтения брошюра остается как локальный предмет в инвентаре результата. Для `calculate_time_to_goal` добавлен тест на понимание сложного процента: 5 вопросов, проходной порог 4/5, повторы без ограничения, серверный proof `compound_quiz_passed`. UI теста вынесен в переиспользуемый `ChallengeQuiz`: пошаговые экраны, один вопрос за раз, поддержка `imageUrl`/`imageAltKey` перед вопросом.

## 2. Предлагаемые новые челленджи (10 штук)

Каждый новый челлендж направлен на решение одной или нескольких стратегических задач:
- **Привлечение** — новые пользователи приходят в систему
- **Core (инвестиции)** — пользователь увеличивает свой неснижаемый капитал
- **Wallet (ликвидность)** — пользователь пополняет кошелёк для операций
- **Внутренний рынок** — пользователи торгуют товарами и услугами внутри системы
- **Удержание** — пользователь возвращается каждый день

---

### 2.1 First Wallet To Core — Первый перевод в Core

| Поле | Значение |
|------|----------|
| Категория | `finance` |
| Уровень | 2 |
| Награда | +1$ Core |
| Длительность | 1 день |
| Проверка | `first_wallet_to_core` — первый перевод Wallet -> Core > 0 |
| Описание | Переведите часть доступного Wallet в Core, чтобы зафиксировать рост Ядра |
| Инструкция | Откройте Кошелёк → Ядро → Перевести из Wallet → введите сумму → подтвердите |

**Стратегическая задача:** увеличение Core без зависимости от внешнего onramp. Пользователь делает первый финансовый шаг внутри системы и видит, как его Core растёт. Внешнее пополнение можно добавить позже отдельным челленджем, когда платежная инфраструктура будет готова.

**Верификация (реализация):** проверять наличие серверной ledger-операции `wallet_to_core` с суммой > 0 для данного `user_id`. Логика добавляется в `verifyChallenge()` через новый case `first_wallet_to_core`.

**Статус:** не включать до появления отдельной ledger-записи Wallet -> Core. Сейчас технический перевод балансов есть, но надежного источника для автопроверки именно первого перевода нет.

## 3.1 Что добавить в следующую ревизию

Чтобы каталог лучше соответствовал концепту `Abundance System`, нужны не только финансовые и рыночные челленджи, но и задания на самопонимание, доверие, вклад и создание маршрута.

| Приоритет | Челлендж | Уровень | Проверка | Зачем |
|-----------|----------|---------|----------|-------|
| P0 | Personal Value Map — Карта сильных сторон | 0-1 | `profile_strengths_filled` | Пользователь фиксирует навыки, интересы, опыт и доступное время |
| P0 | Turn Wish Into 3 Steps — Разбей желание на 3 шага | 1 | `wish_steps_created` | Желание становится маршрутом, а не пассивной мечтой |
| P0 | First Growth Story — Первая история прогресса | 1-2 | `first_growth_post_published` | Закрывает социальный слой: действие превращается в контент |
| P1 | Help Someone Move — Помоги другому сделать шаг | 2 | `trust_event_confirmed:help_given` | Добавляет вклад и взаимную поддержку до marketplace |
| P1 | Skill Passport — Паспорт навыков | 2 | `skill_profile_completed` | Готовит пользователя к заработку на навыках без раннего рынка |
| P1 | Team Welcome — Познакомься с участником команды | 2 | `team_contact_active` | Команда становится отношением доверия, а не только реферальной связкой |
| P2 | Trust Proof — Подтверди надежность | 2 | `trust_event_confirmed:proof_added` | Подготовка Trust-слоя: верифицированный контакт, портфолио, рекомендация или подтвержденный результат |

Эти челленджи лучше поставить перед marketplace-цепочкой. Тогда путь будет ближе к концепту: `самопонимание -> желание -> действие -> прогресс -> вклад -> доверие -> рынок`.

## 3.2 Где нужна проверка другими пользователями

Эти челленджи не стоит засчитывать одной кнопкой пользователя. Их нужно запускать после появления комментариев, ревью, подтверждений или Trust-системы:

| Челлендж | Тип проверки | Что должен подтвердить другой пользователь |
|----------|--------------|--------------------------------------------|
| App Testing | `manual` | Развернутый отзыв реально прочитан командой/модератором |
| Help Someone Move | `community` + `trust_event_confirmed:help_given` | Получатель помощи подтвердил полезное действие через Trust confirmation |
| Fund Someone's Goal | `community` + ledger | Получатель принял поддержку, перевод связан с конкретным `wish_id` |
| Complete a Marketplace Deal | `community` + ledger | Покупатель и продавец подтвердили завершение сделки |
| Earn from Your Skill | `community` + ledger | Платеж пришел от другого пользователя за выполненную услугу |
| Trust Proof | `community` + `trust_event_confirmed:proof_added` | Подтвержден контакт, результат, рекомендация или верифицированный proof |

До появления этих сущностей такие челленджи можно держать в каталоге, но не делать P0-реализацией.

## 4. Логика развития пользователя через челленджи

### Уровень 0-1: Знакомство
- Зарегистрируйся → создай желание → спроси AI → рассчитай цель
- **Итого:** +4$ Core, аккаунт настроен, первые данные введены

### Уровень 2: Привычка
- Три дня фокуса → 7-дневная серия → протестируй приложение → пригласи друга
- **Итого:** +14$ Core, привычка ежедневного действия, первый член команды

### Уровень 3: Инвестиции
- Переведи Wallet в Core → включи реинвестирование → заработай первые 5$ → отправь перевод
- **Итого:** Core-награды без Wallet-эмиссии, реинвестирование активировано, первый перевод

### Уровень 2-3: Рынок и команда
- Создай предложение → вырасти команду до 3 → профинансируй чью-то цель → соверши сделку
- **Итого:** Core-награды без репутации, команда из 3+ человек, первые рыночные операции без лишней эмиссии Wallet

### Уровень 3: Экосистема
- Получи первый платёж за навык
- **Итого:** полный цикл: навык → предложение → платёж → рост

## 5. Требования к реализации

### Новые таблицы (зависят от этапа 10 — Marketplace)
- `marketplace_offers` — предложения на внутреннем рынке
- `marketplace_deals` — сделки между пользователями

### Доработки API
- `app/api/challenges/check/route.ts` — новые cases в `verifyChallenge()`:
  - `first_wallet_to_core` — проверка ledger-операции Wallet -> Core после появления ledger;
  - `first_wallet_transfer` — проверка таблицы переводов
  - `reinvest_enabled` — проверка `core_accounts.reinvest_percent > 0`
  - `core_growth_threshold` — проверка прироста Core от baseline челленджа
  - `team_size_3` — проверка размера команды
  - `daily_streak_7` — проверка серии дней
  - `marketplace_offer_created` — проверка `marketplace_offers`
  - `marketplace_deal_completed` — проверка `marketplace_deals`
  - `first_marketplace_income` — проверка входящего платежа
  - `goal_funding` — проверка перевода с привязкой к цели
  - `profile_strengths_filled`, `wish_steps_created`, `first_growth_post_published`, `skill_profile_completed`, `team_contact_active`, `ai_message_sent`, `has_referral` — проверки для новых ранних челленджей из секции 3.1

Для всех денежных проверок обязательны server-authoritative записи, non-self ограничения, статус `completed`, минимальные пороги и защита от повторного зачета одной операции в нескольких челленджах.

### Миграции
- INSERT новых челленджей в таблицу `challenges`
- При необходимости: добавление индексов для быстрой проверки верификации
