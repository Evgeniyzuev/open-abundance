# UI/UX Refresh и рефакторинг

Статус: принят 2026-10-15, этапы 1-2 в работе (см. «Текущий статус»).

Цель: единый стиль, переиспользуемые формы и контролы, второстепенное под кнопками, чистый и понятный вид, который при этом интересно исследовать. Опорные практики: Instagram (сетка, stories-кольца), TikTok/Reels (вертикальная лента, scroll-snap), Telegram (мгновенный старт из кэша, спокойные ошибки), YouTube (чипы-фильтры, blur-up, редкое под «⋯»).

Связанные документы: [VISUAL_LANGUAGE.md](./VISUAL_LANGUAGE.md), [ADHD_FRIENDLY_INTERFACE_PRINCIPLES.md](./ADHD_FRIENDLY_INTERFACE_PRINCIPLES.md), [ENGAGING_INTERFACE_PLAN.md](./ENGAGING_INTERFACE_PLAN.md).

## Находки аудита

- Скелетон ленты показывался только при `loading && !posts.length`, а `feedLoading` стартует с `false`: до первого запроса мелькал текст «пока пусто», затем серая сетка.
- Кэш ленты жил только в памяти: после перезапуска каждый первый вход ждал сеть.
- 6 чипов-фильтров ленты в одном ряду.
- Кнопки: `text-button` ×144, `secondary-button` ×108, `primary-button` ×12, `danger-button` ×2; `min-height` встречается 7+ раз (30/36/38/40/42/44), скругления 8 значений.
- 32 модалки на сыром `modal-backdrop`; Escape обрабатывают 5 файлов.
- `SocialApp.tsx` 4670 строк (43 `useState`), `WalletApp.tsx` 3891, `lib/i18n.ts` 4930 (все языки в одном объекте), `globals.css` 3149.
- Один `next/dynamic` на весь проект, `AppNavigation` статически импортирует 24 компонента.
- Один скелетон в CSS, 71 использование `app.common.loading` плюс локальные `isLoading`.

## Этап 1. Токены и примитивы

- Токены `--radius-sm/md/lg/pill` (8/12/16/999) и `--control-sm/md/lg` (32/40/48) в `:root`.
- `components/ui/Skeleton`, `components/ui/ChipRow`, `components/ui/Button` как тонкие обёртки над существующими классами (без визуального сдвига), дальше постепенная миграция экранов.
- `<Sheet>`: bottom-sheet на мобильном, центр на десктопе, свайп вниз, Escape и фокус везде. Миграция 32 модалок по одной.
- Правило: на карточке одно главное действие, остальное под «⋯», `<details>` или шторкой.

## Этап 2. Лента и загрузка

- Мгновенный первый экран из локального кэша (первая страница каждого фильтра, по пользователю и языку), фоновое обновление поверх.
- Скелетон с одной крупной герой-карточкой (предзагруженная обложка из `public/onboarding`) вместо 9 серых плиток.
- Состояния: до первого ответа показывается скелетон, а не «пусто»; ошибка показывается спокойно с кнопкой «Повторить».
- Фильтры: «Всё», «Подписки», «Сторис» и чип «Ещё» для остальных.
- Затем: pull-to-refresh и баннер «Новые истории», бесконечная подгрузка вместо кнопки, режим «Лента» (вертикальный scroll-snap), stories-кольца сверху.

## Этап 3. Рефакторинг и производительность

- Нарезать `SocialApp` (`FeedView`, `PeopleHub`, `Teams`, `Profile`, `Notifications`) и вынести хук `useFeed()` (кэш, in-flight, cursor, request-id). Аналогично `WalletApp`.
- `next/dynamic` для вкладок Wallet, Challenges, AiChat, Notes, Tasks при первом открытии (вместе с `KeepAliveView`).
- Один общий `IntersectionObserver` для плиток ленты, `useMemo` для фильтрации и сортировки.
- Сырой `<img>` (18 компонентов) на `next/image` или `ProtectedImage` с размерами и blur-плейсхолдером.

## Этап 4. i18n и CSS

- Разнести `lib/i18n.ts` по языкам (`ru`, `en`), грузить активный; `MessageKey` остаётся от английского.
- Разбить `globals.css` на `tokens`, `primitives` и экранные части, заменить повторяющиеся радиусы, высоты и цвета переменными.
