# Формальная цель ИИ Open Abundance: задача оптимизации

Статус: проект, 2026-10-19, по запросу основателя. Кода по этому документу пока нет. Документ раскрывает математически [AI_CONSTITUTION.md](AI_CONSTITUTION.md), разделы 2 и 7. При расхождении права конституция.

## 1. Короткий ответ

Да, ИИ-координатор решает задачу оптимизации, и её можно записать формально. Это **задача оптимизации с ограничениями во времени** (constrained Markov decision process):

- ИИ выбирает не поступки людей, а **что предложить** каждому человеку (челлендж, связь с другим участником, шаг к желанию, распределение наград).
- Человек сам принимает или отклоняет предложение. Его выбор в модели не управляемая переменная, а внешний закон, который ИИ уважает.
- Цель: сумма благополучия всех участников за долгий срок, где благополучие каждого определяется его собственными желаниями и самооценкой.
- Ограничения: свобода и честность (жёсткие), ресурсы и резерв, правила Core, отсутствие вреда.
- Рост системы в цели **отдельным слагаемым не стоит**. Он появляется сам: больше участников и больше ресурсов значит больше благополучия в будущих периодах. Так рост остаётся средством, а не самоцелью, как требует конституция.

## 2. Обозначения

| Символ | Смысл |
|---|---|
| `t = 0, 1, 2, …` | день |
| `N(t)` | множество подтверждённых участников в день `t` |
| `W_i` | желания участника `i`, которые он сам записал |
| `v_iw ≥ 0`, `Σ_w v_iw = 1` | важность желания `w` для человека `i`, задаёт **сам человек** |
| `p_iw(t) ∈ [0, 1]` | прогресс к желанию: 1 = исполнено и подтверждено |
| `b_i(t) ∈ [0, 1]` | самооценка благополучия (короткий опрос, например 5 вопросов WHO-5) |
| `c_i(t)` | Core участника |
| `h_i(t)` | время и силы, которые человек готов вложить (сам указывает или выводится из ритма) |
| `R(t)` | фонд наград на день |
| `κ(t)` | покрытие резерва (светофор): резерв / выводимые обязательства |
| `O_i(t)` | набор предложений ИИ человеку `i` в день `t` |
| `π` | политика ИИ: правило, по которому выбираются `O_i(t)` |

## 3. Полезность одного человека

```text
U_i(t) = α · Σ_w v_iw · p_iw(t)  +  (1 − α) · b_i(t)
```

- Первое слагаемое: насколько исполнены **его** желания с **его** весами. ИИ не решает, что человеку важно.
- Второе слагаемое: долгосрочное благополучие по самооценке. Оно не даёт гнаться за желаниями ценой выгорания.
- `α` (например 0,6) — параметр протокола, меняется голосованием, а не ИИ.

### 3.1. Уточнения 2026-10-19 (вопросы основателя)

**Важность желаний нормирована на человека.** У каждого участника один и тот же «бюджет важности»: `Σ_w v_iw = 1`. Если поставить всем желаниям максимум, каждое получит `1/n`, и общий вес человека не вырастет. Веса только упорядочивают желания **внутри** одного человека и никому не дают приоритета над другими. Приоритет между людьми задаёт вогнутая `φ`: больше внимания тому, у кого `U` ниже. При равной важности ИИ сначала берёт желания, которые дают больше прогресса на единицу ресурса (раздел 3.2).

**Самооценка благополучия не распределяет ресурсы.** `b_i` субъективна намеренно: благополучие и есть субъективное состояние, и никто, кроме человека, его не знает. Но если низкая оценка давала бы больше помощи, появился бы стимул занижать её. Поэтому:
- при выборе, **кому и что** предложить, используется только прогресс желаний `p_iw` и время (раздел 3.2); `b_i` в этот выбор не входит;
- `b_i` служит для оценки **стратегий** ИИ по группам людей: средний сдвиг `Δb` у тех, кто получал стратегию, против контрольной группы. Один человек не может заметно сдвинуть оценку стратегии;
- `b_i` входит в ограничение вреда 5.6: если у следующих советам благополучие падает, стратегия останавливается;
- за ответ на опрос нет наград, ответ не влияет на собственные награды и видимость человека; учитывается изменение, а не уровень;
- там, где есть проверяемые сигналы (исполненные желания с доказательством, возвраты к делу, отзывы «помогло»), они идут рядом с самооценкой.

Итого для отбора стратегий: `U_i` по разделу 3; для решения, что предложить конкретному человеку: `U_i^предл = Σ_w v_iw · p_iw` без `b_i`.

### 3.2. Единица измерения: время жизни, а не деньги

Ценность денег разная: $10 для того, кто зарабатывает $2 в час, это 5 часов жизни, для того, кто зарабатывает $50 в час, 12 минут. Время одинаково для всех: 24 часа в сутки. Поэтому в модели:

- **Затраты** считаются в часах: `cost(o) = часы_людей(o) + деньги(o) / ставка_эталон`. Деньги переводятся в часы по одной ставке для всех (`ставка_эталон`, например медианный доход участников за час), а не по доходу конкретного человека: так дорогое желание богатого не становится «дешёвым».
- **Польза денег для человека** считается в его часах: `Δ_i = деньги / w_i`, где `w_i` — диапазон его почасового дохода (человек указывает сам диапазоном, данные не публикуются; без ответа берётся медиана региона). Те же $10 дают больше пользы тому, у кого час стоит дешевле. Это дополняет вогнутую `φ`.
- **Вклад** в систему тоже меряется временем: час полезной работы одного участника равен часу другого в наградах за челленджи. Это совпадает с принципом «награда не зависит от статуса».
- **Ограничение сил**: `Σ часы принятых предложений ≤ h_i(t)`. ИИ не может «купить» благополучие, выжимая из человека время.
- Выбор ИИ при равной важности: максимум `Δ(Σ v_iw · p_iw) / cost(o)`, то есть прогресс желаний на час общего ресурса.

Внутренний рынок может предложить и прямой обмен временем (час за час), как банк времени, рядом с обменом за $: см. [MUTUAL_CREDIT_MARKET_PLAN.md](MUTUAL_CREDIT_MARKET_PLAN.md).

## 4. Целевая функция системы

```text
max_π  E [ Σ_{t=0}^{T} γ^t · Σ_{i ∈ N(t)} φ( U_i(t) ) ]
```

- `γ` близко к 1 (например 0,999 в день): будущее почти так же важно, как сегодня. Это и есть «долгосрочное», а не сиюминутное.
- `φ` — вогнутая функция, например `φ(U) = log(ε + U)`. Прибавка тому, у кого мало, весит больше, чем тому, у кого много. Поэтому ИИ выгоднее поднять медиану, чем сделать богаче немногих. Так формально записано правило конституции «медиана раньше суммы».
- Сумма по `N(t)`: каждый новый человек, которому стало лучше, увеличивает цель. Это и есть рост числа участников, но только через пользу для них самих. Регистрация без пользы цель не увеличивает.

## 5. Ограничения

Иерархия конституции записывается так: пункты 1–2 становятся жёсткими ограничениями (их нельзя обменять на пользу), пункты 3–4 входят в цель, пункт 5 работает через динамику.

### 5.1. Свобода выбора (жёсткое)
- ИИ управляет только набором предложений `O_i(t)`. Решение принимает человек: `принял_i(t) ~ выбор человека`, без скрытого воздействия.
- В каждом наборе есть вариант «ничего не делать сегодня», и он не наказывается.
- Человек может видеть и править данные о себе, выйти из рекомендаций, уйти.

### 5.2. Честность (жёсткое)
- Каждое сообщение ИИ проходит проверку конституцией (`scripts/ai-constitution-evals.mjs`): нет манипуляции, давления, обещаний дохода.
- Запрещённые метрики (время в приложении, число сессий) **не входят** ни в цель, ни в признаки, по которым ИИ отбирает стратегии.

### 5.3. Ресурсы
```text
Σ_i награды_i(t) ≤ R(t)                      бюджет наград
κ(t) ≥ κ_min = 1,0  (цель 1,25, зелёный)     резерв покрывает обязательства
Σ_{o ∈ принятые_i} время(o) ≤ h_i(t)         не больше сил, чем у человека есть
```

### 5.4. Привязка 1:1 к $
```text
Σ_t доход_внутренний(t) ≤ Σ_t полезность_созданная(t)
```
Внутренний доход, который можно потратить, не превышает созданную участниками пользу (товары, услуги, привлечённые ресурсы). Это формальная запись принципа «доход за вклад, а не безусловный».

### 5.5. Правила Core (не переменные)
Ставка 0,0633% в день, Core не убывает, не отчуждается, не наследуется. ИИ не может их менять: это параметры протокола (FAIR_ECONOMY_DECISIONS, раздел 2.12).

### 5.6. Отсутствие вреда
```text
P( b_i(t+30) < b_i(t) − δ  | человек следовал предложениям ) ≤ ε
доля жалоб на давление и вред ≤ ε_ж
```
Если благополучие тех, кто следует советам, падает, стратегия останавливается, даже если желания исполняются.

### 5.7. Положительная сумма (мягкое)
Предпочтение действиям, где никому не стало хуже. Штраф в цели за действие, которое улучшает одному ценой другого: `− μ · Σ_j max(0, U_j(до) − U_j(после))`.

## 6. Динамика: как рост системы попадает в цель

```text
N(t+1) = N(t) + приход(t) − уход(t)
приход(t) = f(приглашения, качество опыта участников)
уход(t)   = g(U участников)                  довольные люди остаются
K(t+1)    = K(t) + созданная_польза(t) − потребление(t)    ёмкость системы
R(t+1)    = r(K(t+1), κ(t+1))                фонд наград растёт с ёмкостью
```

Поэтому ИИ, оптимизируя только благополучие людей с длинным горизонтом, сам приходит к росту: больше участников и больше ёмкости дают больше возможностей исполнять желания в будущем. Но рост, который портит опыт людей, повышает `уход(t)` и снижает цель. Total Core и число участников остаются важными показателями, только как следствие, а не как первичная цель.

## 7. Почему цель нельзя оптимизировать «в лоб»: закон Гудхарта

Любая метрика, ставшая целью, перестаёт хорошо измерять то, что нужно. Риски и защита:

| Риск | Защита |
|---|---|
| ИИ подталкивает отмечать желания исполненными | Исполнение подтверждает человек и, где возможно, доказательство или другой участник |
| ИИ подбирает лёгкие желания вместо важных | Веса `v_iw` задаёт человек, ИИ их не меняет |
| Опрос благополучия становится формальным | Короткий, редкий (раз в неделю), без наград за ответ |
| ИИ привлекает людей, которым здесь не место | Учитываются только подтверждённые, уход снижает цель |
| ИИ находит обходной путь, не предусмотренный формулой | Ограничения 5.1–5.2 жёсткие; люди проверяют стратегии; контрольная группа |

Формула никогда не описывает человека полностью. Поэтому она советчик для отбора стратегий, а не замена человеческого решения.

## 8. Как это решать на практике

### Этап 1. Контекстный бандит (сейчас реально)
- У каждого предложения уже записываются `strategy_key` и `outcome_metrics` в `coordinator_recommendations`, измерение каждый день в 03:40 UTC. **[есть]**
- Награда стратегии: изменение `U_i` за 30 дней после предложения. **[предложение]**
- Выбор стратегии: Thompson sampling с ограничениями через множители Лагранжа (стратегия, нарушающая 5.6, получает штраф и уходит).
- **Контрольная группа** 10%: часть людей получает базовые предложения без новой стратегии. Без неё мы видим корреляцию, а не причину. **[предложение]**

### Этап 2. Модель системы (симулятор)
- Цифровой двойник OA: динамика раздела 6 на реальных данных.
- ИИ проигрывает изменения ставок наград, правил челленджей и приёма крупных вкладов и показывает людям прогноз. Решают люди голосованием.

### Этап 3. Ограниченная автономия
- ИИ сам исполняет только действия в выданных лимитах (раздел 7 конституции): например, подбор челленджей и связей. Деньги и правила остаются у людей.

### Роль языковой модели
LLM порождает варианты предложений и объясняет их человеку. Выбор между вариантами делает политика `π` по измеренным исходам, а проверка конституцией отсеивает недопустимые. Так поведение ИИ определяется проверяемой целью, а не только текстом промпта.

## 10. Кто меняет цель

Параметры `α`, `γ`, `φ`, `κ_min`, `δ`, `ε` и сами ограничения являются частью протокола и меняются голосованием участников (FAIR_ECONOMY_DECISIONS, разделы 2.11–2.12), с задержкой вступления в силу. ИИ может предлагать изменения и показывать их прогноз, но не менять их сам.

## 11. Связь с операционной целью координатора

В [AI_COORDINATOR_SYSTEM_GROWTH_PLAN.md](AI_COORDINATOR_SYSTEM_GROWTH_PLAN.md#11-операционная-целевая-функция) приоритет записан как `Total Core → humanity_confirmed_accounts → registrations`. Это операционные показатели, удобные, пока нет данных о желаниях и благополучии. По этому документу они становятся промежуточными сигналами, а главной целью остаётся функция раздела 4. Переход: как только появятся `v_iw` и опрос благополучия, стратегии отбираются по изменению `U_i`, а Total Core остаётся ограничением здоровья системы.
