# Skills System Plan

Статус: канонический продуктовый план системы навыков, 2026-08-01. Реализация не начата. Оперативный порядок задаёт только `MASTER_KANBAN.md`.

## 1. Продуктовый контракт

`Skill Passport` показывает подтверждённые способности пользователя и следующий доступный шаг. Это не самодекларация, не сертификат о просмотре материала и не замена Core Level.

Основные правила:

- уровень навыка повышается только по проверяемому результату;
- `effective_skill_level = min(earned_skill_level, core_level)`;
- рост Core Level может раскрыть уже доказанный уровень, но сам по себе не создаёт новый навык;
- evidence навыка, Trust events и финансовый ledger хранятся раздельно;
- покупка проверки или `peer_point` не покупает положительный verdict;
- первая итерация показывает уровни как RPG-параметры персонажа; сертификаты отложены.

## 2. Начальный каталог

| Код | Навык | Основное доказательство |
|---|---|---|
| `software_creation` | Создание программных решений | работающая фича, git/proof, тестовый сценарий и peer review |
| `content_creation` | Создание контента | материал по брифу и подтверждённое полезное действие аудитории |
| `influence_distribution` | Распространение | качественные переходы, активация и удержание, а не просмотры |
| `referral_acquisition` | Привлечение пользователей | уникальные регистрации на L1, затем активированные участники |
| `mentoring` | Наставничество | подтверждённый прогресс человека, которому помогли |
| `sales` | Продажи | завершённая выручка без возврата или открытого спора |

`vibecoding` — начальный способ освоения `software_creation`, а не отдельный навык. В первом вертикальном срезе реализуются только `software_creation` L1 и `referral_acquisition` L1; остальные направления остаются каталогом развития.

## 3. Уровни и доказательства

Общий смысл уровней:

| Уровень | Результат |
|---:|---|
| 0 | интерес или вводный материал; навык ещё не подтверждён |
| 1 | один базовый принятый результат |
| 2 | несколько результатов или повторяемая качественная метрика |
| 3 | измеримый результат для других с независимой проверкой |
| 4+ | сложные задачи, устойчивые результаты и наставничество |

У каждого навыка есть собственная версионированная rubric. Материал без практического результата может открыть следующий урок, но не повышает подтверждённый уровень.

## 4. Первый vertical slice: `software_creation` L1

Челлендж включает:

1. выбор поддерживаемой среды разработки;
2. краткий актуализируемый обзор AI-моделей и ограничений vibecoding;
3. создание или клонирование репозитория;
4. базовый git-flow: branch, commit, diff и review-flow;
5. небольшую собственную фичу с acceptance criteria;
6. proof: ссылка, описание, тестовый сценарий и известные ограничения;
7. три независимых review от пользователей с таким же или более высоким подтверждённым уровнем.

Зачёт: минимум `2 из 3` review со статусом `pass` и ни одного нерешённого критического замечания. Критическое замечание возвращает работу на доработку и не уменьшает уже заработанный уровень.

Review использует структурированную rubric: воспроизводимость, выполнение критериев, достаточность proof, безопасность и рекомендации к следующему уровню. Проверяющий не получает больше за положительное решение, чем за обоснованный отрицательный verdict.

## 5. `peer_point`

- Обучающий skill-challenge может выдавать один `peer_point`.
- Перед началом review проверяемый передаёт point выбранному проверяющему; передача фиксирует review-slot, но не результат оценки.
- Пользователи позднее смогут продавать review-slot или `peer_point` за Wallet по прозрачной цене.
- Нельзя проверять себя; связанные аккаунты не могут закрыть весь review pool; повторные взаимные проверки ограничиваются.
- До реализации нужно определить цену, момент окончательного списания и возврат point при просроченном или некачественном review.

## 6. Навык привлечения

Простой челлендж `Invite a Friend` и уровень навыка — разные проверки:

- `Invite a Friend`: одна уникальная подтверждённая регистрация после собственного первого результата пользователя;
- `referral_acquisition` L1: рабочий порог — две уникальные подтверждённые регистрации;
- L2: рабочий порог — четыре quality referrals с первым полезным действием;
- L3: рабочий порог — восемь quality referrals, часть которых активна около семи дней;
- следующие уровни используют примерно удвоение порога, пока данные пилота не дадут лучшую кривую.

Регистрационная связь должна быть non-self, уникальной и server-authoritative. Для уровней выше L1 регистрация без активации не считается достаточным доказательством.

## 7. Данные

Минимальные будущие сущности:

- `skills` — каталог и версия rubric;
- `user_skills` — earned/effective level и статус;
- `skill_evidence` — immutable proof и источник;
- `skill_level_rules` — требования уровня;
- `skill_review_requests` и `skill_review_decisions`;
- `skill_progress_events` с idempotency key;
- отдельный ledger `peer_points`.

Самодекларация хранится отдельно и помогает рекомендациям, но не открывает квалифицированные задачи.

## 8. Порядок реализации

1. Схема каталога, evidence и versioned rubric.
2. RPG-блок Skill Passport в профиле без сертификатов.
3. `software_creation` L1 с rework и тремя peer reviews.
4. `peer_point` ledger и защита от review rings.
5. `referral_acquisition` L1 с отдельной server-side проверкой.
6. Автоматические уровни L2+ после данных первой когорты.
7. Подбор квалифицированных задач по навыкам.
8. Остальные навыки; сертификаты и поручительство — отдельная поздняя фаза.

## 9. Метрики и decision gates

Измеряются completion rate обучения, доля принятых практических результатов, время до review, rework rate, расхождения reviewers, доля связанных review-групп и переход из навыка к полезной задаче.

До первой реализации нужно решить:

- кто получает право первого reviewer, пока пользователей нужного уровня ещё мало;
- правила цены и возврата `peer_point`;
- точный порог выручки для `sales` L1;
- когда rubric или evidence устаревают и требуют повторного подтверждения.
