# Open Abundance Master Kanban

Этот документ — единственный канонический источник оперативного статуса Open Abundance. Конкретные решения живут в `OPEN_ABUNDANCE_MASTER_PLAN.md`, накопительный контекст — в `PROJECT_MEMORY.md`; тематические планы не меняют порядок работы в этом канбане.

## Правила работы

- Одновременно в `Сейчас` находится ровно одна главная продуктовая карточка.
- Путь карточки: `Очередь -> Сейчас -> Technical QA -> User QA -> Подтверждено`.
- Написанный код не равен готовому продукту. Без ручной проверки сценария карточка остается в `Технически реализовано / нужен User QA`.
- Перед реализацией следующей карточки фиксируется короткий decision-complete план.
- Код, связанный продуктовый документ и этот канбан обновляются в одной итерации.
- Новые идеи идут в очередь и не прерывают текущий шаг, кроме критических ошибок и угрозы деньгам или данным.
- После frontend-изменений выполняется одна попытка визуальной проверки в in-app browser. Если он недоступен, это явно фиксируется вместе с результатами технических проверок.

## Формат активной карточки

Активная карточка содержит:

- пользовательский результат;
- причину приоритета;
- конкретные изменения;
- что не входит в шаг;
- критерии приемки;
- технические проверки;
- ручной UX-сценарий;
- продуктовую метрику;
- найденные блокеры;
- ссылку на подробный план, если он нужен.

## Сейчас

### Home/Today как главный экран

- **Статус:** Технически реализовано; нужен Technical QA и User QA.
- **Пользовательский результат:** Home открывается первым и за один экран показывает главное желание, Core-цель, прогресс Today и ровно одно следующее действие.
- **Почему сейчас:** ручной onboarding подтвержден пользователем и должен приводить к ежедневному действию, а не оставлять участника в отдельных разделах приложения.
- **Главное решение:** добавить отдельный `home` main tab и сделать его default route. Существующие разделы `Challenges`, `Wallet`, `Goals`, `Ideas` и `Social` остаются доступными напрямую.
- **Источник данных:** Today и его прогресс читать из существующего no-store `/api/today`; активный server growth plan брать из `today.plan`; желание и fallback-план брать из `profile.onboarding_state.firstPlanDraft`. Новый Home API и серверное создание Wish/GrowthPlan в этой карточке не добавляются.
- **Состояния и единственный CTA:**
  - есть server plan, Today не завершен → `Открыть Today`, переход в `Challenges` к Today;
  - Today завершен → `Открыть следующий челлендж`, переход в `Challenges` к рекомендованному доступному действию;
  - server plan отсутствует, но есть onboarding draft → `Рассчитать план`, переход в `Wallet/Core` с открытым калькулятором и draft-параметрами;
  - нет draft → `Собрать план`, переход в `Wallet/Core` с открытым калькулятором;
  - гость с локальным draft видит preview, но primary CTA предлагает сохранить план через Google; серверные Today-прогресс и streak для гостя не симулируются.
- **Изменения:** создать `HomeTodayApp`; добавить Home в навигацию и локализованные ключи; передать из Home явные действия открытия Today/следующего челленджа/Wallet Core; убрать отдельный глобальный Today popup, чтобы Home был единственным первым экраном и местом ежедневного CTA; после возврата на Home повторно загружать Today с `cache: no-store`.
- **Реализовано:** `HomeTodayApp`, default `home` route, Home CTA routing, draft-prefill для Wallet/Core calculator, фокус следующего challenge и встроенное Today-состояние вместо глобального popup.
- **Поведение после действия:** completion challenge или Wallet → Core должны вызвать общий refresh, затем Home должен показать новый `progress_core`, статус Today и новый CTA; нельзя считать прогресс по балансу, только по серверным progress events.
- **Не входит:** Wallet-ввод/вывод, Wallet-награды, реферальные выплаты, публичная лента, local tasks в Today, новая аналитическая схема и полноценное серверное создание Wish/GrowthPlan из onboarding draft.
- **Критерии приемки:** новый и возвращающийся пользователь попадает на Home; на экране присутствует один primary CTA; CTA ведет к актуальному действию; после действия прогресс и CTA меняются; planless-пользователь получает рабочий путь в калькулятор; гость не видит ложный серверный прогресс; прямые `?view=challenges`, `?view=wallet.core` и остальные существующие маршруты не ломаются.
- **Технические проверки:** `pnpm exec tsc --noEmit`, `pnpm lint`, `pnpm test:e2e`; проверить `dynamic/revalidate/fetchCache` и `NO_STORE_HEADERS` для `/api/today`; один раз выполнить ручную проверку в in-app browser.
- **Ручной UX-сценарий:**
  1. новый пользователь завершает onboarding с желанием и draft, попадает на Home и видит желание, цель, Today и `Рассчитать план`;
  2. сохраняет план, возвращается на Home и видит дневной target;
  3. выполняет действие из CTA, возвращается на Home и видит обновленные progress/CTA;
  4. повторяет сценарий для пользователя с завершенным Today и для пользователя без draft;
  5. проверяет гостевой preview, refresh, прямые deep links и возврат браузерной кнопкой.
- **Метрика:** доля сессий с выполненным primary CTA Home/Today и доля возвратов на следующий день; технический guardrail — отсутствие stale Home payload после ручного refresh.
- **Блокеры:** полноценное превращение draft в server Wish/GrowthPlan остается отдельной карточкой; отсутствие in-app browser фиксируется как ограничение проверки, а не как подтвержденный UX.
- **Связанные документы:** `docs/PROJECT_MEMORY.md`, `docs/TODAY_DAILY_CHALLENGE_PLAN.md`.

## Критерии закрытого пилота

- Когорта: 20-50 лично приглашенных русскоязычных пользователей.
- Не менее 70% создают главное желание и сохраняют финансовый план.
- Не менее 50% получают первый проверяемый результат или понимают срок и способ его проверки.
- Ориентиры удержания: D1 >= 40%, D3 >= 25%, D7 >= 15%.
- Не менее 30% активированных участников публикуют карточку результата.
- Не менее 20% активированных участников отправляют приглашение.
- Каждое Wallet-начисление имеет источник, ledger-запись, защиту от повторного начисления и покрытие фондом.
- Демо-контент всегда визуально и семантически отделен от реальных результатов.
