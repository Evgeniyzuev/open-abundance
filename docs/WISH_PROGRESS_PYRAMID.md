# Пирамида желаний Open Abundance

Статус: продуктовая модель зафиксирована 2026-07-20; UI и схема данных пока не реализованы.

## 1. Модель

```text
       /     Единство     \      <- Высший смысл
      /     Признание     \     <- Социальный статус
     /     Реализация      \    <- Раскрытие потенциала
    /        Свобода        \   <- Выбор и автономия
   /      Безопасность       \  <- Фундамент жизни
```

Рабочее название в продукте: **пирамида глубины желаний**.

Это модель смысла желания, а не рейтинг человека и не обязательная последовательность. Желания разных слоев могут существовать одновременно. «Выше» означает более широкий круг влияния, но не большую человеческую ценность.

## 2. Слои

| Слой | Смысл | Примеры желаний |
|---|---|---|
| Безопасность | Укрепить фундамент жизни | здоровье, жилье, закрытие долга, рабочие инструменты, финансовый резерв |
| Свобода | Увеличить выбор и автономию | свободное время, смена работы, путешествие, независимый доход, собственный ритм |
| Реализация | Раскрыть способности и создать ценность | навык, профессия, проект, творчество, бизнес, исследование |
| Признание | Получить доверие и общественное влияние | репутация, аудитория, лидерство, профессиональное признание, команда |
| Единство | Соединить личный путь с высшим смыслом | помощь другим, сообщество, вклад в общее благо, наследие, системное изменение |

## 3. Связь с существующими уровнями

Пирамида желаний и Core-уровни отвечают на разные вопросы:

| Модель | Вопрос |
|---|---|
| Пирамида желаний | «Зачем мне это и какую часть жизни это меняет?» |
| 20 уровней программы | «Где я нахожусь на маршруте возможностей и капитала?» |
| Прогресс конкретного желания | «Какая доля шагов к этому результату уже выполнена?» |

Эти модели нельзя объединять в одну числовую шкалу. Желание уровня «Безопасность» может требовать больше действий и Core, чем желание уровня «Признание». Core не измеряет смысл, а слой пирамиды не определяет размер награды.

## 4. Рекомендуемое место в приложении

Главное место: **Goals -> Wishes**.

После того как у пользователя появится несколько желаний, экран может показать необязательный блок **«Моя пирамида желаний»**:

- пять спокойных горизонтальных слоев;
- карточки или счетчики желаний внутри каждого слоя;
- нажатие на слой фильтрует доску желаний;
- незаполненный слой не считается ошибкой и не создает давления;
- AI может предложить слой, но окончательный выбор всегда подтверждает пользователь.

Лучший момент для знакомства с моделью — после создания первого или второго желания, а не в первом onboarding. В onboarding уже есть одна задача: понять миссию системы и сделать первый шаг.

Дополнительные места в будущем:

- форма создания/редактирования желания: необязательное поле «Что дает тебе это желание?»;
- AI Coordinator: предложение увидеть связь между несколькими желаниями;
- публичный профиль: только если пользователь сам разрешил показывать слой;
- Growth Map: фильтр или смысловая подсветка желаний, но не замена Core-порогов.

## 5. Предлагаемый UX

```text
Пользователь создает желание
-> AI предлагает один слой и коротко объясняет выбор
-> пользователь подтверждает или меняет слой
-> желание появляется в соответствующей части личной пирамиды
-> AI помогает найти следующий конкретный шаг
```

Пользователь может выбрать «Не определять». Классификация не должна блокировать создание желания.

## 6. Будущая модель данных

Если UI подтвердит ценность модели, в `wishes` можно добавить nullable-поле:

```text
aspiration_layer:
  safety
  freedom
  realization
  recognition
  unity
```

До User QA не добавлять миграцию. Сначала достаточно интерактивного прототипа или локальной классификации.

Требования к будущей реализации:

- значение необязательно;
- AI suggestion и user-confirmed value различаются в аналитике;
- изменение слоя не меняет Core, reward, difficulty или visibility;
- слой приватного желания не публикуется автоматически;
- локализация названий идет через общий словарь;
- модель не используется для рейтинга, блокировок или оценки «правильности» пользователя.

## 7. Решение на текущем этапе

- Зафиксировать модель в документации.
- Не добавлять пирамиду в трехэкранный onboarding.
- Поставить будущий блок `Goals -> Wishes -> Моя пирамида желаний` в продуктовую очередь.
- Перед миграцией данных сделать UI-прототип и проверить, помогает ли модель выбирать следующий шаг.
